# 需求分析

识别使用者、触发场景、当前困难、预期结果以及已知约束。先读取已有产品材料，区分用户明确要求、当前实现和提出的设计建议。对会影响方案的缺口提出少量关键问题，其余用清楚标注的假设推进。

用具体输入、操作、状态变化和输出描述需求；覆盖正常流程、空数据、失败恢复与权限差异。划分必须交付与可后续建设的范围，说明每个需求支持什么用户任务。界面文案聚焦业务动作，不把实现参数写进用户流程。

将验收条件写成可观察的行为，例如在给定数据和状态下执行动作应出现什么结果；区分代码、自动检查和真实环境验证。交付自包含需求说明与待决策项，避免用含糊的“智能、稳定、易用”代替行为，不擅自将建议标成已实现。
