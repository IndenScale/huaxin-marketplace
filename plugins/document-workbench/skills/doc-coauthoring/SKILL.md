# 协作文档

确认文档类型、读者、需要支持的决定或动作、已知事实和必须遵守的格式。上下文足够时直接写出可审阅的初稿，不强制让用户回答一整套问卷。通过 read_project 与 read_document 读取已有材料，区分事实、用户观点和待补充内容。

先安排文档主线，让每一部分服务读者的一个问题。缺少关键证据时指出具体缺口，不能用流畅措辞填补未知事实。编辑已有文档时保留用户没有要求改变的事实与约束，压缩重复说明，统一术语、单位和时间。逐段迭代时只提出会影响成稿的选择。

交付前从未看过聊天的读者角度通读：能否知道背景、结论依据、适用范围和下一步；所有必要信息是否在文档内。用户指定格式时使用当前实际可用的保存或导出工具；无专用 Word 工具时不要将 Markdown 改后缀冒充 DOCX。普通文本稿可直接交付，工作文件按授权保存并回读确认。
